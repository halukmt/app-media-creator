# Component inventory

Binding list of all UI components in `src/web/components/`. A new component is added here **before**
its file is created, with a one-line reason and the rejected alternative. `npm run check:inventory`
fails when a component file is missing here or a row points to a missing file.

Layouts (`src/web/layouts/`) and pages (`src/web/pages/`) are not listed; they are composed of these components.

| File | Purpose | DaisyUI | Reason | Rejected alternative |
|---|---|---|---|---|
| `BusyButton.tsx` | Action button that shows a spinner and stays focusable (`aria-disabled`) while its operation runs | `btn`, `loading` | Project save and Export download need the same busy handling; one place for the focus-safe disabled logic | Inline spinner markup per page (second copy, merge rule); `progress` (no known total for a streamed ZIP) |
| `ChecklistCard.tsx` | Export checklist of one store target: title, status badge, items grouped per asset with the languages inside, required marker and messages; OK assets folded away | `card card-border`, `list`, `badge`, `collapse` | Each enabled target shows the same read-only report; up to ~60 rows per target with 6 locales need one consistent layout | Extending `TargetCard` with a mode prop (shares only the card frame; one is a form, the other a report); `table` (unusable at 375 px) |
| `ConfirmDialog.tsx` | Modal confirmation with title, body, confirm and cancel actions | `modal`, `modal-box`, `modal-action`, `modal-backdrop`, native `<dialog>` | "Download anyway" needs an explicit second step; later sections need the same for overwrite and delete | `window.confirm` (unstyled, not themeable); inline acknowledgement checkbox (persistent form state for a one-off decision) |
| `EmptyState.tsx` | L6 empty state: what to upload and which stores need it (badges), optional actions slot | `card card-dash`, `badge` | Five sections need the same "nothing here yet" block; one component keeps wording and layout identical | `alert` (reports an event, not a missing input); `hero` (marketing pattern, too large in a tool UI) |
| `FieldError.tsx` | Error text below a form control, referenced by `aria-describedby` | none (Tailwind, `border-error`) | TextField, LocaleSelector and TargetCard showed the same error markup; one component keeps style and wiring identical | Inline markup in each field (three copies, flagged by code review); `StatusAlert` (too heavy for one line next to a field) |
| `FileField.tsx` | Labelled file picker (multiple, accept) with hint and error | `fieldset`, `file-input` | Screenshot uploads now, logo and video uploads later | Custom drop zone (non-DaisyUI markup, extra keyboard work); extending TextField (only the frame is shared) |
| `LocaleSelector.tsx` | Shared locale selector (L3): single locale, multi-select, "All languages"; built on OptionGroup | via `OptionGroup` | L3 requires exactly one locale control everywhere, including the source locale | `<select multiple>` (poor on touch, no "All"); `filter` (hides the other options); `join` (does not wrap at 375 px); a separate single-locale select (a second selector) |
| `OptionGroup.tsx` | Single or multiple choice as button-styled radio / checkbox options (chip or card variant), with visual, description, disabled state and note badge | `fieldset`, `btn`, `card card-border`, `badge` | Purpose, layout, background, frame, device and the locale options are one pattern (merge rule) | Separate OptionCard and SwatchPicker (same pattern twice); `select` (no swatches); `filter` (hides other options); `tabs` (switch views, not values) |
| `PageHeader.tsx` | Page `h1` + description, focus target after navigation | none (Tailwind) | Every page needs the same heading block and focus handling | A title prop on AppShell (the shell stays unaware of sections; the page owns its heading) |
| `PreviewCard.tsx` | L4 preview: media (render prop), asset name, size, StatusBadge, messages | `card card-border card-sm`, `figure`, `badge` | Screenshot previews now, logo and video previews later | ChecklistCard (a report per store, not per asset); an img-only prop (blocks video) |
| `ProgressStatus.tsx` | L5 progress: bar when the total is known, otherwise spinner, plus a status line (inside a live region) | `progress`, `loading` | Upload and generate progress; replaces inline spinner lines in App and ExportPage | BusyButton alone (no count); `radial-progress` (too large at 375 px) |
| `RequiredBadge.tsx` | Outline marker: "Required" by default, or another short label such as "Comes later" | `badge badge-sm badge-outline` | TargetCard and ChecklistCard showed the same marker markup (design review) | A `required` variant of StatusBadge (a requirement is not a validation state) |
| `SectionEmptyState.tsx` | `EmptyState` filled with one section's text, the enabled stores that need it and the Project link | via `EmptyState` | SectionPage and ExportPage show the same section empty state; one place for the text and store logic | Copying the logic into ExportPage (duplicate); exporting it from SectionPage (one component per file) |
| `SlotEditor.tsx` | One screenshot slot: card preview (media render prop) with StatusBadge and warnings, headline, subline, move / remove, collapsible style override | `card card-border sm:card-side`, `btn`, `collapse` | Up to 10 identical blocks per language | PreviewCard with an edit mode (shares only the frame); `table` (unusable at 375 px) |
| `StatusAlert.tsx` | Feedback line for success, info, warning and error (L5) | `alert` + colour (solid: `alert-soft` fails contrast) | One place for role and aria-live wiring | `toast` (disappears; errors must stay next to their cause) |
| `StatusBadge.tsx` | Validation state as a badge with visible text: OK, Warning, Error (L4) | `badge` + `badge-success` / `badge-warning` / `badge-error` (solid) | Checklist rows, target headers and later the L4 preview cards show the same three states | DaisyUI `status` (a coloured dot, colour-only meaning); `badge-soft` (contrast, as with `alert-soft`) |
| `StepsBar.tsx` | L2 step flow as buttons in order, current step marked | `steps`, `step`, `step-primary` | Every asset section shows the same flow (via SectionLayout) | `tabs` (no order); `timeline` (history, not navigation); `breadcrumbs` (hierarchy) |
| `TargetCard.tsx` | One store target: enabled switch + device model checkboxes with required markers | `card card-border`, `toggle`, `checkbox`, `badge`, `collapse` | Three identical target blocks on the Project screen | Generic Toggle + CheckboxGroup components (one consumer so far); `table` (unusable at 375 px) |
| `TextField.tsx` | Labelled text input or textarea (`multiline`) with hint and error | `fieldset`, `input`, `textarea`, `label` | One frame for label, hint, error and aria wiring | Separate TextListField (same frame, merge rule); `floating-label` (no room for hint and error) |
| `ToggleField.tsx` | Labelled on/off switch, whole row as tap target | `toggle` | Second consumer (shadow) next to TargetCard, which now uses it | Inline toggle again (merge rule); an on/off OptionGroup (wrong control for a boolean) |
